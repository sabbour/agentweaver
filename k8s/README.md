# k8s/ -- Kustomize-based AKS manifests

This directory holds every Kubernetes manifest for Agentweaver's AKS
deployment, packaged with [Kustomize](https://kustomize.io) (built into
`kubectl` -- no separate `kustomize` binary is required for anything this
repo does with it).

```
k8s/
├── base/                 Every deployed manifest, generic placeholder values only
│   └── kustomization.yaml
├── overlays/
│   └── production/       The (currently single) deploy target
│       └── kustomization.yaml
└── reference/            Manifests NOT part of the automated deploy (see below)
```

## `base/`

Every manifest `scripts/azure/steps/30-deploy.mjs` applies during a deploy.
Values here are deliberately generic/static -- no environment-specific
substitution is baked in; that is the overlay's job. Where a manifest used to
carry an `${ENV_VAR}`-style placeholder (image references, hostnames,
workload-identity IDs, Key Vault/tenant IDs), it now either:

- has a static placeholder image tag (`...:latest`) that the overlay's
  `images:` transformer rewrites at deploy time, or
- reads from the `agentweaver-runtime-config` ConfigMap via
  `valueFrom.configMapKeyRef` (generated by the overlay's
  `configMapGenerator`), or
- carries a literal placeholder (`agentweaver.example.com`, `"changeme"`)
  that the overlay's `replacements:` block rewrites at deploy time.

`kubectl kustomize k8s/base` builds standalone (namespace-scoped, no dynamic
values resolved) for a quick structural sanity check.

## `overlays/production/`

The one deploy target this repo has today (matches `variables.mjs`'s
`NAMESPACE` default of `agentweaver`). Add further overlays here (e.g.
`overlays/staging/`) the same way, each referencing `../../base` and
supplying its own `images:`/`configMapGenerator`/`replacements` values.

This is the file `steps/30-deploy.mjs` builds via `lib/kustomize.mjs`: at
deploy time, that module copies this directory (plus `base/`) into a
git-ignored scratch directory and rewrites only the `images:` tags and the
`agentweaver-runtime-config` ConfigMap literals with the real values resolved
from Azure/cluster state (see that module's header comment for the full
pipeline). The committed copy in this repo builds standalone with placeholder
values, for local validation:

```
kubectl kustomize k8s/overlays/production
kubectl apply -k k8s/overlays/production --dry-run=client -o yaml
```

## `reference/`

Manifests that exist for documentation/reference but are **not** part of the
automated `steps/30-deploy.mjs` apply flow, and are therefore excluded from
`base/kustomization.yaml`'s `resources:` list:

- `job-ef-migrate-postgres.yaml`, `job-sqlite-to-postgres-migrator.yaml` --
  manual, one-off migration Jobs (run by hand when needed, not on every
  deploy).
- `sandbox-claim-template.yaml` -- documents the shape of the `SandboxClaim`
  objects the API creates programmatically per run
  (`KubernetesSandboxExecutor.cs`); never applied as a static manifest.
- `secret-agenthost-poc.example.yaml`, `secret-postgres.example.yaml` --
  example/template Secrets for local reference; real values are provisioned
  via Key Vault + `SecretProviderClass`, never committed.

See `docs/deep-dive/infra-deployment.md` and `docs/guide/architecture-aks.md`
for how each deployed manifest fits into the overall AKS architecture.
