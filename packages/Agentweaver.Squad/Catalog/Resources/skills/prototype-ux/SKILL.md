## Method

1. State the user task, hypothesis, fidelity needed, and decision the prototype will inform.
2. Model the happy path plus important alternatives, errors, loading, and empty states.
3. Make assumptions visible rather than simulating certainty with polished visuals.
4. Test comprehension, task completion, and confusion points with representative feedback.

## Output

- Prototype scope and hypotheses
- Critical task flow and state coverage
- Findings, design changes, and unanswered questions
