# API Harness

The API harness drives Agentweaver's REST API and captures objective evidence. Persona cores and API adapters are loaded from `../persona-briefs`; end-of-run verdicts are rendered by `../harness-judge`.

## OpenAPI contract

A running Agentweaver.Api instance serves a machine-readable OpenAPI 3.1 document at:

```
GET /openapi/v1.json
```

This is generated by the built-in `Microsoft.AspNetCore.OpenApi` package (`AddOpenApi()` / `MapOpenApi()` in `apps/Agentweaver.Api/Program.cs`) from the actual minimal-API route registrations, so it reflects real routes and request/response shapes, not a hand-maintained subset. It is registered unconditionally (not gated on `IsDevelopment`) so it is reachable in staging as well as local runs, and it is exempt from GitHub org-membership authorization (see `GitHubOrgAuthorizationMiddleware.ExemptPrefixes`) since it is pure endpoint/schema metadata with no live data — no token is required to fetch it. Example:

```powershell
curl.exe -s https://agentweaver.example.staging.example/openapi/v1.json | jq .
```

**Persona-behavior scenarios (Priya, Jordan, ...) are no longer fixed scripts.** There is no per-persona `scenarios/*.mjs` step sequence to run — Harness dispatches a fresh **`PersonaActor`** sub-agent (`.github/agents/persona-actor.agent.md`) that fully impersonates the persona in an isolated context: it reads the relevant persona-brief + surface adapter, discovers the live API contract via `drive.mjs spec`, and decides every next action live via `drive.mjs call`, one turn at a time, reacting only to the real response — including if/when to push back with a revision, grounded in what it actually received. See `drive.mjs`'s header comment and `.github/agents/harness.agent.md`/`persona-actor.agent.md` for the full model. `run-persona.mjs` remains only for `generated-artifacts-seam` — a deterministic structural conformance check with no persona/pushback dimension.

## Run a persona scenario (dynamic)

These are the primitive commands `PersonaActor` (dispatched by Harness) drives
internally, one at a time, reacting to each real response:

```powershell
node drive.mjs init --brief priya --base-url https://agentweaver.example.staging.example --session my.session.json
node drive.mjs spec --session my.session.json
node drive.mjs call --method GET --path /api/blueprints --thought "..." --session my.session.json
# ...the persona actor continues issuing `call`s guided by the persona brief + spec...
node drive.mjs finish --summary "..." --session my.session.json
```

## Run the generation-seam structural check (fixed, non-persona)

```powershell
npm test
node run-persona.mjs --scenario generated-artifacts-seam --target https://agentweaver.example.staging.example --token <token> --batch-id batch-1 --seed seed-1
```

`--target` is an alias for the legacy `--base-url`. The default rung is `scoping`; deeper approval driving remains opt-in through scenario configuration.

Targets are restricted to localhost or staging hosts at `AgentweaverClient` construction. Production additionally requires both `--allow-prod` and `--i-understand-this-targets-production`; this is independent of the TLS-only `--allow-insecure-prod` flag.

The generated verdict uses `agentweaver.persona-judge-verdict/v1`, including its batch/scenario join key and repro provenance. When running as the `Harness` agent, the preferred judging path is agent-native: build the prompt with `node scripts/harness-judge/core.mjs <evidence.json> --prompt-out <prompt.txt>`, dispatch it via the `task` tool to `agent_type: "Judge"` (`.github/agents/judge.agent.md`, `tools: []` — pure text-in/text-out, no file/shell/network access), then parse and persist the result with `scripts/harness-judge/save-verdict.mjs`. See `.github/agents/harness.agent.md`'s "Judging" section for the exact flow.

For headless/CI use with no agent session to dispatch a `task` call from, set `AGENTWEAVER_JUDGE_CMD` to an external judge command consumed by `core.mjs`'s `makeDefaultJudge()`; without it, a schema-valid `CANNOT_DETERMINE` verdict is emitted.

For the interactive tool driver, pass `--session <path>` (or set `AGENTWEAVER_HARNESS_SESSION`) to isolate concurrent sessions. Without it the legacy `session.current.json` location is retained.
